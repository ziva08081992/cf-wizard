# Рекурсивный обход деревьев Gitea

Предпросмотр сначала ищет дерево в памяти и проверенном дисковом кэше. Для первого отсутствующего поддерева inventory Gitea может получить потомков одним рекурсивным списком по OID дерева. Начальное открытие закреплённого источника и составление манифеста используют прежние запросы.

## Страницы

Запрос отправляется на `git/trees/<OID>` с `recursive=true`, номером страницы и `per_page=1000`. Gitea может уменьшить размер страницы. Клиент сверяет SHA, номер страницы, стабильность `total_count` и уникальность путей. Пустое дерево допускает явный `tree:null` или пустой массив при `total_count=0`. Сбор заканчивается при совпадении числа строк с `total_count`. Последняя непустая страница со старым значением `truncated=true` допускается, если опись затем проходит проверку Git OID. [API Gitea](https://docs.gitea.com/api/operations/get-tree/), [реализация пагинации](https://raw.githubusercontent.com/go-gitea/gitea/main/services/repository/files/tree.go), [историческая ошибка](https://github.com/go-gitea/gitea/issues/35117)

На одно поддерево допускается до четырёх страниц, 4 000 записей, 2 МиБ на страницу и 8 МиБ суммарно. Путь ограничен 4 КиБ UTF-8 и глубиной 128 сегментов вместе с префиксом поддерева. Полный результат на границе лимита проверяется в обычном порядке. Gitea заново вычисляет рекурсивный список для каждой страницы, поэтому превышение `total_count` прекращает запросы сразу.

## Проверка описи

Строки связываются с непосредственными родителями по точным относительным путям. Приведение регистра, удаление лишних разделителей и реконструкция пути по URL или порядку строк не применяются. Для каждого каталога восстанавливается непосредственный список и сверяется канонический Git OID SHA-1 или SHA-256. Проверка идёт снизу вверх и охватывает пустые каталоги и все пути к одному OID. До её завершения выдача не доказывает наличие или отсутствие файлов. [Историческая потеря путей в Gitea](https://github.com/go-gitea/gitea/issues/35959)

Рекурсивные размеры blob служат подсказками, потому что Git не включает размеры в хэш дерева. Перед сетевым чтением blob при отсутствии проверенной локальной копии размер подтверждается прямым запросом к родительскому дереву. Внутренний кэш обычных запросов провайдера заполняется только их собственными ответами.

Отсутствие поддержки, неполный ответ и достижение лимита разрешают обычный обход. HTTP-отказ, ошибка транспорта, ошибка чтения или отмена завершают операцию. Диагностика показывает число рекурсивных попыток и отдельно число запросов страниц. Выигрыш проверяется отдельным замером полного предпросмотра.
