# Хранение SourceFacts V3

V3 меняет физическое представление строк SQLite. Логическая схема SourceFacts остаётся версии 2. При чтении восстанавливаются прежние факты, подписи readers, наблюдения источника и порядок векторов ссылок. Для проверки документа по текущему XML по-прежнему используются path, SHA, span, tag и parent.

V3 хранится в отдельном файле с суффиксом `.source-facts-v3.sqlite3` и контрактом `cf-source-facts-v3`. Внутри строки четыре байта `CFSF` и байт вида предшествуют одному потоку zlib. Маркер `01` означает компактный JSON, `00` означает явно сохранённый V2 JSON для допустимой исторической формы. Неизвестный маркер, лишние данные и неполный поток приводят к отказу. Файл V2 сохраняет прежний немаркированный формат и читатель.

Компактный JSON хранит версии, proof, coverage, имя объекта и пару исходного пути с SHA. Таблица `names` содержит расширенные XML-имена. Узловая строка содержит индекс родителя или `null`, индекс имени, ordinal, kind, name, UUID и исходный span. Индекс родителя указывает только на более ранний узел. В ссылках и coverage notes адрес фрагмента заменён индексом узла. Из узлов восстанавливаются прежние адреса, ключи, родители и полный `origin.node`. Пишущий код проверяет каноническую форму и единое происхождение каждого фрагмента перед выбором компактного варианта.

Лимит распакованного тела составляет 64 МиБ. Декодер ограничивает число строк DTO и до выделения памяти под развёрнутые пути подсчитывает точный объём полного JSON SourceFacts. Проверка использует размер строк с JSON-экранированием и длину пути родителя. Лимит развёрнутого представления также составляет 64 МиБ. Эта величина относится к данным. Пиковая память процесса измеряется отдельно. После восстановления применяются прежние проверки структуры, версий, покрытия и хэша дескриптора.

Явное обновление индекса может создать новый V3 рядом с V2. Предпросмотр читает доступный поддерживаемый индекс. Старый файл остаётся доступен для предыдущей версии, которая пропускает новый контракт. Для совместимых неизменившихся строк закреплённого Git-источника преобразование использует старые проверенные факты. Локальный источник сохраняет проверку хэша актуального XML. Повреждение закреплённой строки остаётся ошибкой.

## Проверка производительности

Отдельный тест `frozen_822_compact_source_facts_pipeline` использует локальную синтетическую выборку `facts-workload-v1` со сверкой SHA XML и прежних V2-строк. Режим `prepare` создаёт две SQLite-копии для измерений с одной схемой таблицы объектов и проверяет равенство фактов по каждой строке.

Режимы `v2-owned`, `v2-borrowed` и `v3-borrowed` разделяют стоимость копирования BLOB и эффект компактного представления. Тест проводит 822 различных документа через проверку XML и повторяет четыре lookup после проверки документа. В отчёте учитываются 78 структурных проекций, отдельные этапы SQL, inflate, JSON, проверки и разворачивания, CPU, wall time и пиковый рабочий набор. SHA полного результата считается после замера. Измерение полного предпросмотра и обновления индекса выполняется отдельно.

## Damaged legacy migration

Migration fails without publishing V3 if an old V2 payload is malformed. The old file is retained. Local preview retains its authoritative XML fallback. To rebuild without trusting the damaged V2, select a new empty SQLite index folder and run Update Index; keep the old folder for investigation. No automatic deletion or repair of the old file occurs.
