# Проверки owned SQLite без повторного чтения больших записей

Новый checker сохраняет результат проверки внешних ключей для точно распознанной схемы owned index. Физический формат SQLite и SourceFacts V2 не меняется. Старые файлы открываются без миграции; неизвестная схема использует исходный `PRAGMA foreign_key_check`.

## Причина затрат

В используемой SQLite 3.50.2 native FK checker обходит дочерние строки и ищет родителя в B-tree. Для overflow-записи сравнение ключа может читать всю запись, включая большой `facts` BLOB в `objects WITHOUT ROWID`. Это не означает полный обход всех BLOB в любом индексе: затраты зависят от размеров отдельных записей и числа поисков. На RDP физические чтения страниц не измерялись.

Быстрый путь один раз читает ключи родителей в ограниченный `HashSet`, затем последовательно проверяет ключи детей. Он не извлекает `facts`. Все пять запросов явно выбирают первичный B-tree через `INDEXED BY sqlite_autoindex_<table>_1`; `NOT INDEXED` для WITHOUT ROWID здесь недостаточен.

## Условия эквивалентности и fallback

До быстрого пути проверяются точные DDL всех таблиц и индексов относительно текущей SCHEMA, полный перечень семи разрешённых таблиц, фактические определения всех трёх FK, UTF-8 encoding, TEXT NOT NULL первичные ключи и BINARY collation. Owned headers должны содержать schema=2 и прежний facts contract. Дополнительный индекс, изменённая связь или неизвестная схема ведут к native проверке.

Ключи сравниваются полными UTF-8 байтами, включая встроенный NUL. Невалидный UTF-8 и не-TEXT значения используют native fallback. Родительский набор ограничен 100000 ключей, 4096 байт на ключ и 16 МиБ расчётного бюджета с накладными расходами. Дети читаются потоком. Превышение бюджета также использует native путь. Все классы детей проверяются до принятия быстрого verdict, чтобы позднее неподдержанное значение не скрывалось ранее найденным orphan.

Checker общий для открытия/readiness и pre/post update проверок. `quick_check`, семантические проверки, manifest, полнота Git inputs и границы read transaction сохранены. Connection и результаты не кэшируются между открытиями. WAL, in-place изменение и атомарная замена проверяются на новом snapshot следующего открытия.

При чтении Git manifest возвращаются manifest и digest, уже проверенный при десериализации. Тот же digest используется только в текущем открытии, вместо повторной сериализации и SHA. Публичный `read_manifest` сохраняет прежний контракт; новые fingerprints не вводятся.

## Наблюдаемость и проверки

Сохранён общий `index.foreign_key_check`; добавлены вложенные `index.fk_schema`, `index.fk_fast`, `index.fk_native`. Повторное использование manifest отмечено `index.fingerprint.stored_reuse`. Метрики не содержат имён исходных объектов или payload.

Адресные тесты сравнивают результат с native PRAGMA: valid и каждый orphan, дополнительные/изменённые FK, DDL и collation, UTF-16, BLOB и malformed UTF-8, Unicode/case/NUL, ограничения, WAL и замена файла. EXPLAIN подтверждает root pages первичных B-tree даже при добавленных покрывающих индексах; наличие таких индексов запрещает быстрый путь.

G2 на неизменяемой синтетической модели 750538752 байт (715.77 МиБ), с отдельными 73728-байтовыми opaque facts BLOB для моделирования overflow-страниц (декодирование V2 проверяется отдельно): девять соседних AB/BA пар, свежий процесс и readonly connection, одна прогревочная пара. Три отдельные копии с нарушенными FK дают одинаковую ошибку baseline/candidate.

| Этап | Baseline median | Candidate median | Baseline p95 | Candidate p95 |
|---|---:|---:|---:|---:|
| FK | 2779.07 мс | 12.76 мс | 2843.20 мс | 13.48 мс |
| Полное открытие | 3142.40 мс | 373.70 мс | 3201.87 мс | 391.12 мс |
| quick_check | 356.85 мс | 352.88 мс | 366.13 мс | 368.79 мс |

G2 пройден: FK −99.54%, открытие −88.11%. Все samples сохранены, SHA файлов и исполняемых probes проверены до/после. OS page cache не контролировался; это не cold-disk и не прогноз конкретного времени на RDP. Raw receipts находятся в изолированном audit-каталоге `cf-wizard-preview-optimization-20261119/bench/sqlite/runs-g2-final`, вне публичного checkout.

Откат — прежний checker/native PRAGMA; удаление индекса и миграция для этого не нужны. Новый GUI EXE и повторный RDP запуск остаются отдельной поставкой и runtime-проверкой.
