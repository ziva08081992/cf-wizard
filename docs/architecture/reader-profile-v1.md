# Поддерживаемый профиль чтения CF Wizard 0.8.5

План помечается `reader_profile: cf_input_v1`. Это профиль существующих читателей, подключённых к новому вычислителю Datafrog, а не заявление о полной поддержке языка 1С или любого XML.

| Вход | Что извлекается |
| --- | --- |
| Описания объектов Designer XML | Типы реквизитов, составные/определяемые типы, поля и колонки табличных частей; совместимые факты `facts-v1` из SQLite |
| Ссылки XML | Известные имена метаданных и их частей; структурированные типы и `MDObjectRef` с проверкой namespace отдельно подтверждают обязательные ссылки |
| Управляемые формы | Статические типы атрибутов, `DataPath`, поддерживаемые ссылки и псевдонимы из текста запросов динамических списков |
| BSL | Поддерживаемые литералы `VALUE` / `ЗНАЧЕНИЕ`; ссылки только в комментариях остаются необязательными |
| Предопределённые данные | Запрошенный режим переноса и предупреждения о кодах; требуемый файл проверяется до сборки |
| Ресурсы | Известные общие картинки и стили; полное содержимое зависимостей `CommonPicture` / `Style`, включая ZIP |

Пути проходят без прежнего ограничения глубины восемь. Циклы ограничиваются конечным множеством требований и посещённых пар «тип — позиция пути». Когда позднее включается ещё один подходящий документ-регистратор, пути форм оцениваются повторно по сохранённым результатам разбора; XML ради этого заново не разбирается.

Не заявляются общий граф вызовов BSL, вычисление динамически составленных имён и строк запросов, универсальное чтение произвольных DCS/XDTO/HTML и независимая проверка всех зарегистрированных видов метаданных на платформе. Ограничение буквального префикса `style:` для `StyleItem` остаётся известной границей. Полный перенос общих форм и макетов как самостоятельная новая политика не добавлялся.

`complete` означает отсутствие подтверждённых ошибок в этом профиле. Это не подтверждение всех возможных зависимостей пользовательского кода. Обычный текст и неподдерживаемые динамические выражения не объявляются обязательной отсутствующей ссылкой только по совпадению шаблона.

Подтверждённое отсутствие объекта, поля, структурного кандидата или обязательного файла показывается в неполном предпросмотре. Найденный состав сохраняется для диагностики; сборка блокируется интерфейсом и application-слоем до создания staging. Ошибки чтения/разбора и повреждённые доверенные payload не заменяются пустыми «успешными» фактами.

SQLite сохраняет прежний формат и доказательства источника. Предпросмотр читает её без обновления; пересчёт исключений использует тот же вычислитель и собственный неизменяемый снимок прочитанных фактов. Контекст Datafrog, причины и структурные решения прошлого запроса в снимок не переносятся.

Планируемая новая реализация читателей обсуждается отдельно. При изменении смысла чтения потребуется явно версионировать профиль и правила совместимости сохранённых фактов; смена версии EXE сама по себе не должна запускать полное перечитывание индекса.
