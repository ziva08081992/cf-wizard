# Дисковый кэш деревьев Git на SQLite

Для описей деревьев Gitea мастер проверяет память процесса, SQLite, прежний файловый кэш и затем обращается к провайдеру. Начальные запросы, подтверждающие закреплённую ревизию, выполняются по прежним правилам. Каждый кандидат из дискового кэша проходит ту же проверку контрольной суммы записи, имён, режимов и канонического Git tree OID. Размеры blob остаются подсказками. Правила подтверждения размера перед запросом blob описаны в [справке по кэшу деревьев Gitea](gitea-tree-cache.md).

SQLite хранит записи по OID в `tree-cache-sqlite-v1/<identity>/trees.sqlite3`. Идентификатор изолирует провайдера, адрес сервера, репозиторий, каталог конфигурации и формат OID. В БД хранится хэш идентификатора. Одна транзакция публикует пакет полностью проверенных деревьев. Предел SQLite составляет 1024 записи и 1 МиБ на пакет, включая отдельную запись. Слишком большой пакет использует прежнюю атомарную публикацию файлов JSON с пределом 16 МиБ на запись.

Перед чтением и записью мастер проверяет путь к БД и служебным файлам SQLite на ссылки и reparse points. Занятость, сбой проверки или ошибка SQLite переводят чтение к файловому кэшу. Следующий шаг при промахе — запрос провайдера. Mutex соединения и транзакции удерживаются только на локальных операциях с кэшем. Отмена прекращает операцию и откатывает текущую незавершённую транзакцию.

Явное обновление индекса дополнительно импортирует проверенные прежние записи JSON ограниченными транзакциями. Оно сохраняет прежние файлы и использует импорт как ускорение. Недоступность SQLite оставляет файловый кэш доступным. Предпросмотр читает существующие записи обоих форматов.

Один pager до 8 МиБ резервируется на весь процесс. Другие одновременно открытые хранилища устанавливают `cache_size=0`. SQLite mmap для деревьев отключён. Лимит описывает настройку pager, общий рабочий набор процесса включает также данные приложения, структуры SQLite и ОС.

Профиль включает `cache.tree_sqlite_read`, `cache.tree_sqlite_hit`, `cache.tree_sqlite_rejected`, `cache.tree_sqlite_write`, `cache.tree_sqlite_write_fallback`, `cache.tree_legacy_hit` и `cache.tree_legacy_import`. Метрики pager показывают настроенный и эффективный размер в КиБ и mmap в байтах.

Локальный стенд измеряет запись и чтение 10 000 проверенных синтетических деревьев при файловом и SQLite-хранилищах. Каждое чтение после перезапуска выполняется в отдельном процессе. Явный импорт измеряется отдельной фазой с проверкой побайтового совпадения записей. Отдельный стенд полного предпросмотра сравнивает артефакты пакета между версиями мастера. Оба сценария ограничены локальными синтетическими данными.
