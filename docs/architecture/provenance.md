# Происхождение компонентов CF Wizard 0.8.7

## Текущая локальная версия 0.8.7

После описанного ниже состояния 0.8.5 в версии 0.8.6 реализована согласованная замена source readers и выдачи. Версия 0.8.7 сохраняет этот конвейер и оптимизирует Windows metadata queries. Текущие рабочие owners — `source_xml/source_reader/source_schema/reference_lexer`, `source_forms/source_query/source_literals`, `projection/source_edits/package_compiler/emission_guard`, `identity/predefined/facts_cache` и их адаптеры engine/indexing. Старые metadata/forms/query и старые stub/merge producers оставлены только под `cfg(test)` для offline compatibility controls. Рабочего fallback на них нет.

Нормативные таблицы и конечные compatibility policies сохраняют историческую преемственность. Добавлены независимо построенные source/model row/branch cases; они подтверждают поведение конечного профиля, а не универсальную минимальность XML платформы. Lookup fold отделен от внешней Unicode collision library. Подробные [границы реализации и версии семантики](owned-source-profile.md) описаны отдельно.

Результаты code/performance/UI checks и границы переноса исторических native receipts записаны в [приёмке 0.8.7](../reports/cf-wizard-0.8.7-acceptance.md). Карта runtime producers не отменяет исторические сведения, уведомления или вопросы прав. Ни 100% self-written, ни юридический clean-room не заявляются.

## Состояние выпущенной версии 0.8.5

Проверка проведена 15 ноября 2026 года. Она разделяет текущую реализацию по компонентам; собственное новое ядро не означает, что все остальные части проекта были написаны независимо.

| Компонент | Текущее состояние |
| --- | --- |
| `kernel.rs` | Новая реализация типизированного положительного замыкания поверх Datafrog 2.0.1; Python-helper не вызывается |
| `requirements.rs` | Новая нормализация требований, идентификаторы по потребности, конечные непосредственные причины и метрики запроса |
| `engine_normalize.rs` | Новый координатор явных структурных решений и диагностик; использует сохранённые читатели и таблицы правил |
| `engine.rs` | Чтение и политика путей/использования частично происходят из переноса; рабочее замыкание и пересчёт исключений подключены к Datafrog |
| `metadata.rs`, `kinds.rs`, `cf-domain::fold` | Сохранены перенесённые помощники чтения ссылок/типов, ограниченного folding, таблицы метаданных и генерация служебного UUID |
| `forms.rs`, `query.rs` | Сохранена перенесённая логика поддерживаемых путей форм, литералов и запросов |
| `stubs.rs`, `package.rs` | Сохранены части проекции XML, упаковки, предопределённых данных и настроек объединения; рабочий проектор исполняет окончательный план |
| Native/readback, SQLite, Git API, хранилище токенов, журнал и оболочка | Собственные компоненты мастера и их библиотечные зависимости; стандартные команды 1С и условия библиотек учитываются отдельно |

В закреплённом Python-источнике подтверждён SHA256 `efe67eda5f95475757efefd75c979d8144ffd7480934307db487155c87ea5699`, commit `8cc8aff3705dd91100555851d398ae91a192e23d`. Сопоставлены функции `scan`, `type_keys`, `index_members`, `stable_uuid`, `query_refs`, `module_values`, `form_paths`, `clean_properties`, `stub_descriptor`, `merge_settings` и `predefined_codes`. У 14 сопоставленных таблиц правил сохранены значения.

Одинаковые имена классов и свойств платформы сами по себе не доказывают заимствование защищаемого кода. Здесь вывод о сохранённом переносе также опирается на зафиксированную историю порта и сопоставление структуры функций. Это не заключение о правах и не подтверждение clean-room разработки.

Для будущей замены обсуждаются собственные читатели, проектор и генератор настроек при сохранении нынешнего комплекта CF + `.merge-settings.xml`. [Вариант последовательной замены](own-readers-and-projection-options.md) отделён от текущей реализации. Такая замена в версии 0.8.5 не заявляется выполненной. Благодарность историческому прототипу и условия фактически сохранённых частей — разные сведения; уведомления нельзя убирать только из-за смены вычислителя.
