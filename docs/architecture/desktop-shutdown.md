# Закрытие окна Windows

Если выполняется операция, кнопка закрытия отправляет запрос отмены. Окно остаётся открытым. Когда операция завершена, пользователь может закрыть его снова.

При закрытии свободного окна мастер сохраняет изменённые настройки и передаёт план предпросмотра, ссылки на источник и Git-клиент одному фоновому потоку. После передачи окно скрывается. Поток окна продолжает обработку системных сообщений до уведомления об окончании очистки. Старый опрос Git может удерживать собственную ссылку. Новые прикладные операции в этот период не запускаются. На последнем этапе WebView2, его контекст и окно освобождаются в потоке интерфейса.

Если фоновый поток нельзя запустить или передача отклонена, модель сохраняет владение и применяется прежнее синхронное закрытие. Штатный код процесса равен 0, перехваченная паника фоновой очистки даёт 1. Ошибка записи настроек сохраняет прежнее поведение.

При запуске через диагностический launcher в выбранной папке журналов появляется отдельный файл `*-shutdown-*.jsonl`. Он отмечает сохранение настроек, передачу, освобождение плана и ссылок, завершение фоновой работы и `loop-destroyed`. Последняя фаза предшествует уничтожению WebView2. При принудительной остановке могут сохраниться только первые строки. Диагностика с выключенным профилем и при ошибке записи не мешает штатному закрытию.

Проверка Windows `tools/cf-wizard-rust/tests/native_close.py` принимает `--exe`, `--fixture` (синтетическая Designer-выгрузка с общим модулем) и `--out` (новая папка). Параметр `--profile` включает диагностический режим. Проверка отправляет два WM_CLOSE собственному тестовому окну, проверяет WM_NULL во время управляемой задержки освобождения готового плана, затем проверяет завершение процесса и сохранённое значение настройки. Последний этап измеряется внешним процессом.
