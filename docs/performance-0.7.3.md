# CF Wizard 0.7.3: индекс и запуск

## Git-индекс

Синтетическая выгрузка: 1003 XML-входа, 1002 индексируемых объекта, Windows. API заменён проверяемым MemoryGit; это не замер корпоративного сервера и не всей ERP УХ.

| Сценарий | Проверка SQLite | Обновление | Получение XML |
|---|---:|---:|---|
| Первое построение | — | 6,682 с | 1002 описания, 51 пакет; Configuration получен при открытии |
| Та же SHA | 3,57 мс | не выполняется | без скачивания описаний |
| Новая SHA, изменён только BSL | 3,73 мс | не выполняется | без скачивания описаний |
| Один изменённый XML | 0,35 мс, нужен update | 43,31 мс | один пакет, один файл |

SQLite: 221184 байта (216 КиБ). При повторном использовании байты и время изменения SQLite не меняются. Само открытие Git проверяет Configuration и деревья; это отдельная стадия. Проверка готовности не читает XML. При одном изменении обработан один XML, фактических Path.read_bytes по этому файлу — два (проверка Git и извлечение фактов), неизменные XML на стадии обновления не читаются. Полный журнал и счётчики: [git-index.json](benchmarks/0.7.3/git-index.json).

## Загрузка окна

Замер: от создания процесса до готовности локальной HTML-страницы. Qt сообщает loadFinished; Rust дополнительно проверяет DOM, кнопки и CSS. Для каждого запуска отдельный тестовый профиль. Кэш ОС не очищался; «первый успешный» не означает строго холодный запуск. Два прогона на вариант, порядок Qt portable → Qt onefile → Rust; это ориентир для этого компьютера, а не статистическая гарантия.

| Вариант | Первый успешный | Повторный | Полнота |
|---|---:|---:|---|
| Полная программа, портативная папка | 4,065 с | 0,567 с | весь мастер |
| Полная программа, один EXE | 9,834 с | 5,510 с | весь мастер |
| Rust + Wry/WebView2 | 2,378 с | 0,490 с | только оболочка с тем же макетом |

Rust-прототип: 909312 байт (~0,87 МиБ); использует уже установленный системный WebView2. Python/Qt EXE: 197143753 байта (~188 МиБ); внутри около 490 МБ runtime. Поэтому сравнение размеров не доказывает, что весь мастер после переноса будет весить 0,87 МиБ.

Из упаковки исключён один отладочный ресурс qtwebengine_devtools_resources.debug.pak: 81573852 байта после распаковки. Остальные 10 ресурсов, QtWebEngineProcess, переводы и библиотеки сохранены. Сверены 17 скомпилированных модулей, пять UI-файлов и закреплённый helper каждого варианта; оба EXE открыли WebEngine и завершились с кодом 0.

## Выбор подхода

Для текущей версии переносимый ZIP уже убирает повторную распаковку и даёт быстрый запуск без установщика. Один EXE сохранён как отдельный вариант поставки.

Для будущей лёгкой оболочки Rust/WebView2 — рабочий кандидат. Потребуется перенести Qt/JS-канал, диалоги, фоновые операции, ошибки и защищённое хранение токена и проверить весь сценарий. Функции мастера в Rust-прототипе пока отсутствуют. Перенос индексатора следует обосновывать профилем CPU на реальной конфигурации: новый инкрементальный Python-маршрут уже обрабатывает только изменённые XML.

Ещё один вариант исследования — Nuitka с постоянным versioned-кэшем onefile. Он поддерживается самим упаковщиком, но в этой работе не компилировался и не измерялся.

Первичные источники: [PyInstaller onefile и onedir](https://pyinstaller.org/en/stable/operating-mode.html), [Tauri и системные WebView](https://v2.tauri.app/reference/webview-versions/), [Wry API](https://docs.rs/wry/0.57.2/wry/), [Nuitka: onefile cache](https://github.com/Nuitka/Nuitka).

## Границы приёмки

114 Python-проверок и два отдельных Qt/WebEngine-сценария прошли. Отдельно проверены блокировка двух OS-процессов и освобождение после аварийного завершения собственного тестового процесса. Алгоритм и смысловая реализация прошли два независимых ревью. Работа с настоящими приватными API и реальная сборка CF платформой 1С/перенос в базу получателя остаются пользовательским пилотом.
