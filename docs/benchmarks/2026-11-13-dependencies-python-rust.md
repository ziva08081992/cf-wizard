# Зависимости: Python 0.7.3 и Rust 0.8.0-rust.1

Замер 13.11.2026 на одной рабочей XML-выгрузке УправлениеХолдингомERP. **На этих наборах общий выигрыш скорости определения зависимостей после переноса на Rust пока не получен.** На простом модуле без индекса ядро Rust быстрее; на справочнике, регистре и смешанном наборе оно медленнее.

## Что и как сравнивалось

- В каталоге 28292 выбираемых объектов, 28294 XML-описания с учётом языков.
- Использованы действующие Python TechnicalPackage.prepare/resolve_dependencies и действующий Rust RustEngine.preview; изменены только отдельные измерительные обвязки. GUI и создание CF не запускались.
- Для каждой комбинации: один прогрев каждой версии, затем три измеряемые пары в чередующемся порядке. Каждый образец — отдельный headless-процесс; запуск процесса, импорт библиотек и первичное открытие каталога не входят во время расчёта.
- Кэш ОС не очищался. Чтение XML, файловые проверки и открытие готовой SQLite входят в измеряемый расчёт.
- Два режима: локальная XML-выгрузка без индекса и та же выгрузка с одним общим SQLite-файлом. Сетевой Git и его режим доверенного SHA-манифеста не измерялись.
- Общий индекс построен Python до замеров: 15,781,888 байт (15.05 МиБ), 28294 записей; построение 32.99 с исключено из таблиц. Индекс после всех чтений не изменился.
- В Python проверки ConfigDumpInfo/Configuration выполняются снаружи resolver, в Rust внутри preview. Для таблицы ядра из Rust вычтено отдельно измеренное время Source.snapshot. Это время алгоритма с файловым IO, а не чистое CPU-время. Полный предпросмотр приведён отдельно и сохраняет все проверки обеих реализаций.

## Найденный резерв

В Rust преобладает работа слоя источника: перечисление каталогов, поиск принадлежащих объекту файлов, проверки путей/ссылок и чтение. Сумма времен непересекающихся вызовов этого слоя в измеренных SQLite-прогонах составляет около 87–97% времени движка для справочника/регистра/смешанного набора. Особенно дорог Rust LocalSource.list_directory: он проверяет путь каждого найденного элемента и его родителей; одни и те же родительские пути проверяются многократно. Время перечисления только для справочника составляло примерно 0.7–0.8 с.
Следующий обоснованный шаг — сократить повторные обходы и проверки одних родительских путей, сохранив защиту от reparse points и изменения исходников. В текущем задании оптимизация рабочего алгоритма не выполнялась. SQLite в локальном режиме сохраняет проверки XML и регистраторов; поэтому наличие индекса само по себе эти расходы не устраняет.

## Проверка равенства и границы

- Во всех 64 образцах (включая прогревы) совпали выбранные объекты, имена заглушек, первичные/все причины и их обязательность, сохраняемые члены и предупреждения. Числа заглушек: 0 / 8 / 84 / 92.
- Отслежены 1042 прочитанных исходных файла; общие hash не менялись. Configuration.xml/ConfigDumpInfo.xml и инвентарь XML-описаний остались неизменны. Общая SQLite читалась без изменений.
- Один из трёх смешанных SQLite-прогонов Rust дал 4.224 с полного предпросмотра; медиана3.382 с. Разброс не скрыт.
- Это сравнение выбранных объектов текущей выгрузки в локальном режиме. Его нельзя переносить на любые объекты, максимальные пакеты или сетевые подключения Git.
- В готовый EXE изменения не вносились. Проверена прежняя SHA256 доставки: ae67c89734424e56c121ff558f0455f70f06322f7fffb702d0d2665ca9a5d06b.
