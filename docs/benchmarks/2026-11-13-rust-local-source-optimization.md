# Rust LocalSource: оптимизация и повторные замеры, 13.11.2026

На справочнике, регистре и смешанном наборе полный предпросмотр Rust ускорился в 2,85–3,59 раза. Узкий путь общего модуля существенно не изменился. Состав комплекта сохранён.

## Что изменено

В `tools/cf-wizard-rust/crates/infrastructure/src/source.rs` добавлен private guard для LocalSource. На Windows он запрашивает свежие атрибуты каждого компонента пути через GetFileAttributesW. При отказе используется стандартный `symlink_metadata`, в том числе для корня UNC share. Уже полученный тип конечного элемента используется в том же `exists`/`list_directory`.

Число проверок цепочки родителей не сокращено; ускорена стоимость самой проверки. Повторные списки внутри Session уже кэшировались. Проверки перед/после чтения, обычного файла по открытому handle, reparse points, Unicode casefold collisions, отмены, хешей и повторной актуальности плана сохранены. Дополнительно корень проверяется перед перечислением, включая пустой каталог. Кэш положительных результатов проверки путей не добавлен.

Публичный `no_links`, его write/native/index/Git-потребители, `engine.rs`, `package.rs` и `git_source.rs` не изменены. Требуемые повторные проверки перед/после материализации не заменены кэшем предпросмотра.

API: [Microsoft GetFileAttributesW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfileattributesw), [Rust DirEntry::metadata](https://doc.rust-lang.org/std/fs/struct.DirEntry.html#method.metadata). На Windows прежний `DirEntry::metadata` может использовать сведения перечисления, поэтому его удаление само по себе не доказывает устранение системного вызова.

## Методика

Прежняя XML-выгрузка УправлениеХолдингомERP: 28 292 выбираемых объекта, 28 294 описания с языками. Скопирована та же SQLite: 15 781 888 байт (15,05 MiB), без изменения её содержимого. Python/helper и драйвер сравнения прежние.

Наборы:

- `CommonModule.ZipАрхивы`: 0 заглушек.
- `Catalog.Валюты`: 8 заглушек.
- `AccumulationRegister.АмортизацияОС`: 84 заглушки.
- Эти три объекта вместе: 92 заглушки.

Для каждой пары набор/режим выполнен один прогрев и три измерения каждого движка, порядок Python/Rust чередовался. Всего 64 отдельных headless-процесса. Инициализация каталога, создание/обновление индекса и запуск процесса не входят во время предпросмотра. OS-кэш не очищался. CF, staging и Git HTTP не выполнялись.

«Прежде» — сохранённый предыдущий прогон, «теперь» — повторный прогон после оптимизации. Python повторно измерен как контроль условий. Поэтому это локальные результаты данной машины, а не гарантия ускорения на любом диске или SMB.

## Расчёт зависимостей отдельно

Внутри Rust resolver выполняются две проверки snapshot, которые Python делает снаружи resolver. Для сопоставимой границы из Rust вычтено замеренное время этих вызовов. Остались чтение файлов, проверки путей, открытие индекса и сам алгоритм; это не чистое CPU-время. Медианы в режиме SQLite, секунды:

| Набор | Rust прежде | Rust теперь | Python теперь |
|---|---:|---:|---:|
| Общий модуль | 0,022 | 0,019 | 0,018 |
| Справочник | 0,939 | 0,190 | 0,138 |
| Регистр | 2,619 | 0,851 | 1,591 |
| Смешанный набор | 3,275 | 0,909 | 1,680 |

На справочнике скорректированный расчёт Rust всё ещё медленнее Python. Полный предпросмотр Rust быстрее за счёт остальных частей сценария. Общий модуль почти не выиграл в полном времени: его путь уже короткий, заметная доля приходится на snapshot. Локальная SQLite сохраняет необходимые XML-проверки и не гарантирует ускорения каждого выбора.

## Проверки

- Все 64 результата совпали между Python/Rust и XML/SQLite: выбранные объекты, заглушки, основные и все причины, обязательность, члены и предупреждения. Отдельное сравнение с предыдущим прогоном также подтвердило совпадение.
- Хеши всех 1042 отслеженных файлов совпали между прогонами; Configuration.xml, ConfigDumpInfo.xml и общая SQLite не изменились.
- 61 workspace-тест прошёл, включая прежнюю differential matrix 16 сценариев в двух режимах с совпадением полного пакета по байтам. `cargo fmt --check` и Clippy `--all-targets -D warnings` прошли.
- Новые адресные тесты: добавление/изменение/удаление и замена типа файла; Unicode casefold collision; отмена; junction после открытия источника; длинные/отсутствующие/недопустимые пути; эксклюзивно открытый файл `share_mode(0)`. Для последнего быстрый и стандартный guard дали одинаковый результат; чтение отказало.
- Независимое ревью эффективности, обоснованности и смысловой части Full Path завершено без подтверждённых блокирующих замечаний по финальному хешу.

Реальные UNC/SMB, нестандартные ACL и отдельная файловая symlink не проверялись. Junction/reparse проверен фактически. Проверки пути не являются атомарной гарантией против произвольной конкурентной подмены файловой системы. GUI/native CF и приватные Git повторно не запускались: их реализация не менялась. GUI EXE не пересобран и не заменён. Commit/push/внешняя публикация не выполнялись.
