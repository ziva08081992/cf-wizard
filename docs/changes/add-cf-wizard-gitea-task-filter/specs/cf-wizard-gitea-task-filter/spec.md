## Purpose

Подбирать объекты XML-выгрузки 1С для технической CF по номеру задачи из коммитов открытой ревизии Gitea.

## ADDED Requirements

### Requirement: R1. Поиск задачи в открытой ревизии Gitea

Мастер SHALL искать ключ задачи в сообщениях коммитов, достижимых из SHA открытой ветки. Ключ Git вводится в отдельное поле. Поиск выполняется по явной команде. UC-01.

#### Scenario: Точный номер задачи

- **WHEN** разработчик ищет ERP-123 и в истории встречаются ERP-123 и ERP-1234
- **THEN** мастер сопоставляет ERP-123 без учёта регистра и учитывает только совпадение полного ключа

#### Scenario: Период поиска

- **WHEN** разработчик запускает поиск
- **THEN** мастер показывает фактические границы поиска и предлагает «Последние 90 дней» по умолчанию, «Указать дни…» и «Вся история» в общем тёмном меню

#### Scenario: Произвольное количество дней

- **WHEN** разработчик выбирает «Указать дни…», вводит положительное целое N и запускает поиск
- **THEN** мастер передаёт в API выбранного сервиса интервал от текущего момента UTC минус N суток до текущего момента
- **AND** сохраняет привязку к открытому SHA, постраничное чтение, отмену и прежние правила поиска ключа

#### Scenario: Некорректное количество дней

- **WHEN** в своём периоде введено пустое, неположительное, дробное значение либо период не представим поддерживаемой Git API датой
- **THEN** мастер сообщает причину до HTTP и сохраняет предыдущий отбор и отметки
- **AND** при выборе всей истории поле дней не ограничивает поиск

#### Scenario: Смена источника или ветки

- **WHEN** выбран источник «Локальная папка» или ещё не открыта выбранная ветка Gitea
- **THEN** поиск недоступен до открытия нужной ветки
- **AND** отбор очищается при открытии другой ревизии

### Requirement: R2. Сопоставление изменённых путей с деревом

Мастер SHALL объединять изменённые пути из совпавших коммитов в пределах каталога выгрузки и сопоставлять их с объектами открытой ревизии. UC-01.

#### Scenario: Несколько изменений одного объекта

- **WHEN** несколько совпавших коммитов меняли один модуль, форму и XML одного справочника
- **THEN** справочник появляется в дереве один раз, а результат показывает число коммитов, уникальных путей и найденных объектов

#### Scenario: Вложенный файл или объект удалён

- **WHEN** совпавший коммит удалил форму существующего объекта или удалил сам объект
- **THEN** мастер включает существующий объект с удалённой формой и отдельно учитывает путь объекта, отсутствующего в текущем снимке

#### Scenario: Совпадений нет

- **WHEN** история выбранного периода прочитана до конца и подходящих путей нет
- **THEN** мастер показывает пустой результат с периодом и счётчиками, чтобы разработчик мог расширить поиск или сбросить фильтр

### Requirement: R3. Использование результата в дереве

Мастер SHALL показывать найденные объекты как фильтр дерева, позволяющий сохранить ручной выбор и явно отметить все найденные объекты. UC-01.

#### Scenario: Отмечены другие объекты

- **WHEN** разработчик выполняет поиск, отмечает найденные и снимает фильтр
- **THEN** ручные отметки сохраняются и к ним добавляются найденные объекты
- **AND** изменение состава требует нового предпросмотра по действующему сценарию

#### Scenario: Поиск отменён или оборвался

- **WHEN** разработчик отменяет поиск или мастер получает сетевую ошибку либо неполный ответ
- **THEN** мастер сообщает, что поиск не завершён, и сохраняет предыдущий фильтр, отметки и предпросмотр
