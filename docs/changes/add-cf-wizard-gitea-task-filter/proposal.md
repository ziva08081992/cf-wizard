## Why

Разработчик знает номер задачи из сообщений коммитов Gitea, но сейчас вручную переносит названия изменённых объектов из истории в дерево мастера. Отбор по номеру задачи должен сразу показать доступные объекты открытой ревизии для последующей сборки технической CF.

## What Changes

- Добавить в режиме Gitea поиск по точному ключу задачи, например ERP-123. По умолчанию проверять последние 90 дней и показывать границу периода. В общем тёмном меню предусмотреть «Последние 90 дней», «Указать дни…» с положительным целым N и «Вся история». Использовать существующий поиск и отмену для Gitea и GitHub.
- Объединить изменённые пути совпавших коммитов в каталоге выгрузки и показать в дереве существующие в открытом снимке объекты. Отдельно показать число путей, которым нельзя сопоставить доступный объект.
- Дать команду «Отметить найденные» и сброс фильтра. Сохранять ручные отметки. Номер задачи Git вводится отдельно от комментария к комплекту.
- Зафиксировать границы изменения. Режим локальной папки, настройки авторизации, поиск зависимостей и формат CF продолжают работать по действующим требованиям. Jira, сборка исторической версии и автоматический перенос удалений находятся вне сценария.

## Use Cases

### UC-01: Найти объекты для технической CF по номеру задачи

Разработчик открывает нужную ветку Gitea, вводит ключ задачи и запускает поиск. Мастер показывает число коммитов, файлов и доступных объектов с указанием ветки, SHA и периода. Разработчик проверяет найденные объекты, отмечает их вручную или группой и продолжает обычный предпросмотр.

Связанные требования R1, R2, R3.

## Capabilities

### New Capabilities

- cf-wizard-gitea-task-filter — поиск изменённых объектов XML-выгрузки по номеру задачи в коммитах открытой ревизии Gitea.

### Modified Capabilities

Нет.

## Impact

Затрагиваются Python-клиент Gitea, чтение каталога XML и Qt/HTML-интерфейс CF Wizard. Используется действующий токен чтения и REST API Gitea 1.25.3. Конфигурации, расширения, BSL и XML-метаданные 1С не изменяются.
