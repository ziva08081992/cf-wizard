## Purpose

Сохранять пригодность Git-индекса зависимостей между запусками и ревизиями при одинаковых проверенных XML, а при изменениях обновлять только затронутые данные по явной команде разработчика.

## ADDED Requirements

### Requirement: R1 Полные проверенные входы

Мастер SHALL определять пригодность индекса по текущей закреплённой ревизии, полному составу входных XML, их blob SHA, владельцам, ролям, helper и версиям фактов. Входы включают Configuration.xml, описания всех его объектов, включая Language, и все непосредственные Documents/*.xml для регистраторов.

#### Scenario: Configuration прежний а тип реквизита изменён

- **WHEN** Configuration.xml совпадает, но изменилось описание типа в XML справочника или определяемого типа
- **THEN** мастер обнаруживает изменение входов и показывает необходимость обновления

#### Scenario: Документ вне списка Configuration

- **WHEN** в непосредственном каталоге Documents добавлен или удалён XML документа, отсутствующего в Configuration
- **THEN** мастер учитывает его изменение для фактов регистраторов

### Requirement: R2 Повторное использование без записи

При совпадении входов, источника, ветки, helper и версий мастер SHALL использовать сохранённую SQLite при новой SHA без повторной индексации и изменения байтов индекса. Проверка SHALL выполняться вне UI-потока; частое обновление формы не инициирует HTTP.

#### Scenario: Новый запуск и новая SHA с изменением BSL

- **WHEN** изменён модуль, а входные XML индекса прежние
- **THEN** после открытия ветки индекс готов и команда обновления не требуется
- **AND** прежний предпросмотр другой SHA не используется

### Requirement: R3 Явное инкрементальное обновление

При изменённых входах мастер SHALL показывать «Нужно обновить» и выполнять обновление только по кнопке. Он SHALL обрабатывать добавленные и изменённые XML и удаления, не читая и не хешируя неизменные XML ради обновления индекса.

#### Scenario: Изменён один XML

- **WHEN** разработчик нажимает «Обновить индекс» после изменения одного описания
- **THEN** мастер проверяет и обрабатывает это описание и необходимые роли этого файла, сохраняет остальные проверенные факты и выводит счётчики
- **AND** сетевое содержимое берётся из проверенного кэша либо запрашивается только при его отсутствии

#### Scenario: Удаление или переименование

- **WHEN** текущий состав входов больше не содержит прежний путь или владельца
- **THEN** соответствующие факты удаляются, а новые пути обрабатываются как добавленные

### Requirement: R4 Совместимость старых индексов

Мастер SHALL сохранять действующий локальный формат и явный безопасный переход старого Git-индекса. Индекс без манифеста SHALL NOT считаться совместимым с другой SHA только по имени файла или Configuration.xml.

#### Scenario: Старый Git-индекс

- **WHEN** индекс ещё не содержит доказательства полного состава входов
- **THEN** он доступен для прежнего точного SHA-контракта при его выполнении, а перенос на другую SHA требует кнопки и однократной полной сверки
- **AND** при совпавшем helper проверенные прежние факты могут быть сохранены по содержимому

#### Scenario: Изменён helper

- **WHEN** изменился helper или смысл формата фактов
- **THEN** совпадение XML не подтверждает пригодность прежних фактов и явное обновление извлекает их заново

### Requirement: R5 Согласованность предпросмотра и CF

Готовый индекс SHALL работать при выборочном наличии файлов в Git-снимке. Предпросмотр и сборка SHALL проверять полную идентичность входов и читать нужные файлы текущей SHA с проверкой Git hash; локальные проверки файловой системы сохраняются.

#### Scenario: В новом снимке есть только Configuration

- **WHEN** входы совпадают с готовым индексом, а нужные файлы ещё не материализованы
- **THEN** предпросмотр и сборка получают требуемые файлы текущей ревизии и не требуют копировать все неизменные описания

### Requirement: R6 Изоляция и безопасный отказ

Мастер SHALL разделять индексы провайдеров, серверов, репозиториев, каталогов и веток. Он SHALL проверять совместимость в согласованном снимке SQLite и публиковать успешное обновление атомарно, сохраняя прежний файл при ошибке, прерывании или конкурентной замене.

#### Scenario: Доказать полноту не удалось

- **WHEN** дерево неполное, blob повреждён, источник изменён или обновление не завершено
- **THEN** мастер не объявляет неподтверждённый индекс готовым, сохраняет прежние данные и показывает причину с журналом

### Requirement: R7 Наблюдаемость

Мастер SHALL журналировать проверку готовности и обновление, источник и SHA, итог совместимости, количество входов и изменений и длительность без токенов и заголовков авторизации.

#### Scenario: Повторное открытие

- **WHEN** входы не изменились
- **THEN** журнал подтверждает повторное использование индекса и отсутствие извлечения неизменных фактов
