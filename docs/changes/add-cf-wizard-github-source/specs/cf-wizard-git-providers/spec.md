## Purpose

Обеспечить разработчику один сценарий подготовки технической CF из файлов Gitea или GitHub с сохранением точности зависимостей, изоляции секретов и совместимости существующих подключений.

## ADDED Requirements

### Requirement: R1 Выбор Git API

Мастер SHALL показывать на главной форме источники «Локальная папка» и «Git». В окне «Подключение Git» пользователь SHALL выбирать Gitea или GitHub; интерфейс SHALL показывать сервис фактически открытой ревизии. Связь: UC-01.

#### Scenario: Подключение GitHub
- **WHEN** выбран GitHub и проверено подключение к доступному репозиторию GitHub.com
- **THEN** доступны ветки и открытие каталога выгрузки через GitHub API с теми же командами дерева, индекса, предпросмотра и сборки CF

#### Scenario: Ошибка нового подключения
- **WHEN** проверка нового подключения завершилась ошибкой или пользователь отменил окно
- **THEN** предыдущие открытая ревизия, выбор объектов и результат предпросмотра сохраняются

### Requirement: R2 Совместимость Gitea

Сохранённые настройки без API SHALL трактоваться как Gitea. Мастер SHALL сохранять доступ к прежней записи токена, кэшу и совместимой SQLite Gitea; локальный источник SHALL продолжать работать. Связь: UC-01.

#### Scenario: Старые настройки
- **WHEN** приложение читает существующие настройки без указания сервиса
- **THEN** выбирается Gitea и используются прежние адрес, репозиторий, ветка, папки и запись Windows Credential Manager

#### Scenario: Повторный запуск
- **WHEN** пользователь сохранил подключение GitHub и перезапустил приложение
- **THEN** выбор GitHub и его параметры восстановлены, а секрет отсутствует в файле настроек

### Requirement: R3 Изоляция доступа

Токен SHALL использоваться только для выбранного сервиса и канонического HTTPS-адреса; сохранение SHALL выполняться только по явной отметке пользователя. Мастер MUST NOT переносить токен Gitea в запросы GitHub, хранить секрет в настройках/журналах/UI-снимках или отправлять его через HTTP-перенаправление. Изменение API SHALL очищать введённый токен и флаг сохранения. Связь: UC-01.

#### Scenario: Переключение API
- **WHEN** в окне с введённым токеном Gitea пользователь выбирает GitHub
- **THEN** секрет очищен, чужой сохранённый токен не читается, ветки прежнего подключения не предлагаются как ветки нового

#### Scenario: Удаление токена отредактированного подключения
- **WHEN** пользователь нажимает «Удалить токен» после изменения сервиса или адреса
- **THEN** удаляется только запись выбранного сервиса и адреса; запись другого сервиса сохраняется

#### Scenario: Перенаправление или ошибка доступа
- **WHEN** API возвращает redirect, 401/403 либо ошибку с телом, содержащим секрет
- **THEN** токен не передаётся по новому адресу, секрет не показывается, операция завершается понятной безопасной ошибкой

### Requirement: R4 Целостная выборочная загрузка

Ветка SHALL открываться как закреплённый SHA. Мастер SHALL загружать необходимые файлы и XML-описания без полного ZIP/клона, проверять их размер и Git hash, разделять GitHub/Gitea кэш и SQLite-идентичность. Недоступный, усечённый или повреждённый ответ MUST NOT публиковаться как полный индекс. Связь: UC-01.

#### Scenario: Движение ветки
- **WHEN** HEAD изменился во время загрузки
- **THEN** все файлы текущей операции и её индекс относятся к исходно закреплённому SHA

#### Scenario: Индекс крупной выгрузки
- **WHEN** создаётся индекс из десятков тысяч XML-описаний
- **THEN** XML загружаются пакетно с ограниченным объёмом ответа, а не отдельным HTTP-запросом для каждого XML; содержимое модулей/форм загружается по необходимости

#### Scenario: Ошибка пакета либо нехватка лимита
- **WHEN** пакет XML неполон, содержит ошибки или API запрещает дальнейшее чтение
- **THEN** новый индекс не заменяет прежний, пользователь видит причину; разрешения токена автоматически не расширяются

#### Scenario: Разные сервисы с одинаковым путём
- **WHEN** совпадают имена репозитория, ветки и каталога у Gitea и GitHub
- **THEN** их кэш и индекс не считаются одним источником; проверка содержимого сохраняется при повторном использовании blob

### Requirement: R5 Полный отбор объектов по задаче

Для GitHub мастер SHALL сохранять точное сопоставление ключа задачи, пагинацию истории закреплённой ревизии и отображение объектов текущего каталога. Путь из большого коммита MUST NOT теряться из-за ограничения списка файлов API. Merge SHALL сравниваться с первым родителем; переименование SHALL учитывать старый и новый пути, начальный коммит — пустое исходное дерево. Связь: UC-01.

#### Scenario: Коммит более 3000 файлов
- **WHEN** совпавший по задаче коммит изменил более 3000 файлов
- **THEN** отбор учитывает все подходящие пути каталога выгрузки либо явно завершается ошибкой полноты; неполный успешный результат запрещён

#### Scenario: Переименование и удаление
- **WHEN** совпавший коммит переименовал или удалил вложенные файлы объектов
- **THEN** учитываются оба пути переименования, существующие владельцы сопоставляются с открытым каталогом; отсутствующие в нём объекты не подменяются другими

#### Scenario: Отмена длительного обхода
- **WHEN** пользователь отменяет поиск во время получения путей большого коммита
- **THEN** новые запросы прекращаются после текущего ограниченного по времени запроса, предыдущие отбор, отметки и предпросмотр сохраняются

### Requirement: R6 Наблюдаемые ошибки и безопасная публикация

Существующий журнал SHALL фиксировать выбранный сервис и безопасную причину ошибок чтения/индекса без PAT. Изменение SHALL публиковаться отдельным PR с результатами проверок и явной границей между синтетическими тестами и реальным private-GitHub пилотом. Связь: UC-01.

#### Scenario: Недоступен private-репозиторий
- **WHEN** PAT не даёт доступа к выбранному репозиторию либо действует ограничение организации
- **THEN** мастер показывает причину отказа и оставляет прежний каталог/индекс; пользователь самостоятельно решает вопросы доступа

#### Scenario: Слияние PR
- **WHEN** выполнены адресные тесты, Qt smoke и обязательные ревью реализации
- **THEN** PR содержит только эту доработку и документацию, показывает непроверенные runtime-сценарии и сливается после проверки точного head/base по имеющемуся разрешению пользователя
