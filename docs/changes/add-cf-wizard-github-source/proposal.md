## Why

Мастер уже получает XML-выгрузку из Gitea, но жёстко связывает Git-источник с её API. Разработчику нужен тот же сценарий для GitHub: открыть ветку, выбрать объекты вручную или по задаче, определить зависимости и собрать техническую CF.

## What Changes

- На главной форме источник называется «Git», рядом отображаются фактический сервис и открытая ветка.
- В окне «Подключение Git» выбирается API: Gitea или GitHub. Фабрика создаёт соответствующую стратегию; выбор объектов, SQLite и сборка используют общий контракт.
- GitHub.com поддерживает ветки, закрепление ревизии SHA, выборочную загрузку файлов и существующий отбор по точному ключу задачи. XML для индекса читаются пакетно; полный архив репозитория не загружается.
- Секреты, кэш и SQLite-идентичность GitHub отделяются от Gitea. Старые настройки без указания API, сохранённый токен и кэш продолжают означать Gitea.
- Публикация: отдельная ветка `codex/`, проверки, PR в частном `ziva08081992/cf-wizard`, затем разрешённое пользователем слияние.

### Границы

Первый вариант поддерживает Gitea по настроенному HTTPS-адресу и GitHub.com. GitHub Enterprise, GitLab, OAuth, запись в исходные репозитории, Jira, автоматическое расширение прав токена, ZIP/clone и пересборка EXE не входят в эту доработку. BSL/XML конфигураций и расширений 1С, информационные базы и хранилище не изменяются; номер ERP для служебного инструмента не требуется.

## Use Cases

### UC-01: Подготовить техническую CF из выбранного Git-сервиса

**Актор:** разработчик. **Цель:** получить комплект из нужных объектов актуальной ветки Gitea или GitHub. **Триггер:** выбор «Git» и подключение к репозиторию. **Результат:** открыта закреплённая ревизия, работают дерево, индекс, отбор по задаче, предпросмотр и существующая сборка CF.

Альтернативный API остаётся вариантом этого сценария, а не отдельным use case. Связанные требования: R1–R6.

## Capabilities

### New Capabilities

- `cf-wizard-git-providers`: выбор Git API, безопасная авторизация, совместимость Gitea и полный доступ к файлам/истории GitHub через общий контракт.

### Modified Capabilities

Нет: предыдущие возможности Gitea описаны в незавершённых change-артефактах, а не в опубликованных основных specs. Их действующие требования сохраняются и проверяются регрессией.

## Impact

Исходники: `.local/1c-delivery/cf-wizard-repository/tools/1c-delivery/cf_wizard/` — Git-клиенты и фабрика, `qt_view.py`, `qt_git_dialog.py`, `paths.py`, `git_credentials.py`, UI HTML/JS; адресные тесты и README. Общий механизм файлов/кэша отделяется от конкретного API без замены алгоритма зависимостей и SQLite-схемы.

Внешние интерфейсы: Gitea REST, GitHub REST и read-only GraphQL. Секрет остаётся в памяти либо в Диспетчере учётных данных Windows по явной отметке пользователя; в настройки, журналы и UI-снимки не записывается. Доступ к частному GitHub с минимальными правами PAT проверяется отдельно на пилоте.
