# Сборка CF Wizard

Текущая версия **0.8.0-rust.2** находится в `tools/cf-wizard-rust`. Для запуска готового EXE Rust, Python и Qt не требуются; разработчику для сборки нужны Rust MSVC x64 и Microsoft C++ Build Tools. Проверенный toolchain — Rust 1.99.1. Для окна приложения нужен Microsoft Edge WebView2 Runtime, для сборки CF — установленная платформа 1С x64.

## Rust workspace

Из корня репозитория перейдите в workspace:

```powershell
Set-Location tools/cf-wizard-rust
cargo fmt --all --check
cargo check --workspace --locked
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo build --release --locked
```

Результат: `target/release/cf-wizard-rust.exe` внутри workspace, либо каталог из `CARGO_TARGET_DIR`. Для распространения переименуйте копию в `CF-Wizard-0.8.10.exe`. HTML/CSS/JavaScript встроены в EXE. `Cargo.lock` закрепляет зависимости; `.cargo/config.toml` включает статический C runtime для Windows MSVC x64.

Обычная сборка и тесты не запускают Python. Сохранённые эталоны для сопоставления с Python 0.7.3 включены в `tests/fixtures`; Python-генераторы нужны только для их повторного получения.

Состав слоёв и детали запуска: [README Rust-версии](tools/cf-wizard-rust/README.md). Границы проверок rust.2: [описание выпуска](docs/releases/v0.8.0-rust.2.md). Успешные unit-тесты и обратная выгрузка не подтверждают совместимость объединения с целевой информационной базой.

## Платформа 1С и команды сборки

Проверенная платформа пилота — **8.3.27.2214, Windows x64**. На ней выполнены успешные сборки CF с обратной выгрузкой через Конфигуратор и ibcmd в `0.8.0-rust.1`; результаты записаны в [VALIDATION.md](tools/cf-wizard-rust/VALIDATION.md#реальные-cf). Работа с другими версиями платформы пока не подтверждена.

Известное ограничение `rust.2`: в пользовательском прогоне на 8.3.27.2214 все шесть шагов Конфигуратора завершились успешно и CF была создана, но итоговое структурное сравнение обнаружило отличие XML одного справочника. Проверка отклонила результат. Журнал не содержит различающихся XML-узлов, поэтому причина пока не установлена; проверка целостности сохранена. Этот случай не доказывает несовместимость версии платформы и не позволяет обещать успешную сборку любой XML-выгрузки.

Режим **Авто** ищет точно Конфигуратор 8.3.27.2214. При отсутствии этой версии автоматического перехода на более новую нет. В ручных режимах жёсткого списка версий нет: проверяются имя EXE, архитектура Windows x64 и наличие версии в ресурсах файла. Изменение платформы во время сборки приводит к ошибке. Выбор другой версии сам по себе не подтверждает её совместимость.

Ниже перечислены фактические вызовы из [native.rs](tools/cf-wizard-rust/crates/infrastructure/src/native.rs). Это команды внешних процессов, а не методы BSL или COM. `<stage>` — подготовленная XML-папка, `<db>` — новая временная база сборки, `<checkdb>` — отдельная временная база обратной проверки, `<data>` — служебный каталог ibcmd, `<cf>` — выходной файл, `<back>` — XML обратной выгрузки. Рабочая информационная база пользователя в этих вызовах не используется.

### Пакетный Конфигуратор

Все строки запускаются через выбранный `1cv8.exe`.

| Аргументы | Назначение |
| --- | --- |
| `CREATEINFOBASE File="<db>";` | Создать временную файловую базу сборки. |
| `DESIGNER /F "<db>" /LoadConfigFromFiles "<stage>"` | Загрузить подготовленную XML-конфигурацию. |
| `DESIGNER /F "<db>" /DumpCfg "<cf>"` | Выгрузить техническую CF. |
| `CREATEINFOBASE File="<checkdb>";` | Создать отдельную базу для проверки. |
| `DESIGNER /F "<checkdb>" /LoadCfg "<cf>"` | Загрузить полученную CF для обратной проверки. |
| `DESIGNER /F "<checkdb>" /DumpConfigToFiles "<back>" -Format Hierarchical` | Получить иерархическую XML-выгрузку для сравнения. |

К `DESIGNER` добавляются `/DisableStartupDialogs`, `/DisableStartupMessages`, `/DisableSplash`, `/DisableBackgroundIndexBuild`. Создание базы использует `/DisableStartupDialogs`. Во всех вызовах Конфигуратора мастер также передаёт `/Out "<step.out>"` и `/DumpResult "<step.result>"`; проверяются код процесса и результат `DumpResult`.

### Автономный инструмент ibcmd

Все строки запускаются через выбранный `ibcmd.exe` из `bin` установленной платформы вместе с её библиотеками.

| Аргументы | Назначение |
| --- | --- |
| `infobase create --db-path="<db>" --data="<data>"` | Создать временную базу. |
| `config import --db-path="<db>" --data="<data>" --out="<cf>" "<stage>"` | Импортировать подготовленный XML и получить CF. |
| `config export --db-path="<db>" --data="<data>" --file="<cf>" "<back>"` | Выгрузить XML из CF для обратной проверки. |

Проверяются нулевой код завершения, наличие непустой CF и результат обратной выгрузки. BSL-файлы сравниваются побайтно, XML — по структурной сигнатуре; дополнительно проверяется неизменность подготовленного комплекта и EXE платформы. Этот контроль подтверждает целостность технического комплекта, а функциональность объединения с целевой базой проверяет разработчик.

## Обновление инструкции Word

Источник текста — `docs/user-guide.md`. Актуальные реальные скриншоты — `docs/images/rust-0.8.0-rust.2`. Для подготовки Word нужен отдельный Python с `python-docx`:

```powershell
python tools/docs/build_user_guide.py
```

Результат — `docs/CF-Wizard-0.8.0-rust.2-User-Guide-RU-Illustrated.docx`. Параметры `--source`, `--output` и `--version` позволяют собрать другую редакцию без изменения генератора. Комментарий `<!-- pagebreak -->` в Markdown задаёт начало страницы в Word.

Перед публикацией откройте Word, обновите поля и проверьте каждую страницу, таблицу и подпись. Допустим рендеринг через Word либо LibreOffice с просмотром всех страниц. Внешние ссылки в Word преобразуются в адреса GitHub, поэтому документ можно читать отдельно от репозитория.

Иллюстрированный Word имеет отдельное имя: он не подменяет текстовую инструкцию и `SHA256SUMS.txt`, опубликованные в Assets тега `v0.8`.
