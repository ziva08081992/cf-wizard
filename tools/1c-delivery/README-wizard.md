# Мастер технической CF

Черновик пользовательской инструкции.

## Запуск

Запустите `CF-Wizard-0.7.1-git-pilot-windows-x64.exe`. В файл входят Python, HTML-интерфейс на Qt WebEngine и закреплённый сборщик `partial_cf.py`. Мастер собирает CF через `ibcmd.exe` или пакетный Конфигуратор `1cv8.exe` из папки `bin` установленной платформы 1С.

Мастер проверяет контрольную сумму сборщика при запуске. Кнопка **Справка** или клавиша F1 открывает инструкцию по сборке. В окне **О программе** указана версия и есть ссылка на репозиторий сборщика.

## Сохранение путей

Пути к выгрузке, результату, журналам и индексу, способ сборки и выбор платформы доступны через кнопку **Настройки**. На главной панели находятся команды открытия выгрузки или ветки, обновления индекса и открытия папки журналов.

При закрытии мастер сохраняет пути к XML-выгрузке, результату и журналам, способ сборки и отдельные пути к `ibcmd.exe` и `1cv8.exe` в `%LOCALAPPDATA%\CF-Wizard\paths.json` текущего пользователя. При следующем запуске эти поля заполняются сохранёнными значениями. Если выбран локальный источник, мастер автоматически открывает сохранённую выгрузку.

Кнопки выбора начинают с папки, указанной в своём поле. Если в поле указан файл, диалог начинает с его папки. Для пустого поля или недоступного пути используется последняя доступная папка, которую мастер запомнил для этого поля. Пути отображаются с разделителем `\`.

## Подключение Git: Gitea или GitHub

Выберите источник **Git** и откройте **Настройки → Подключение Git**. Выберите API **Gitea** или **GitHub**. Укажите HTTPS-адрес сервиса, репозиторий в формате `владелец/репозиторий`, каталог выгрузки и ветку. Введите персональный токен чтения. При явном согласии Windows запоминает токен для текущего пользователя на этом компьютере. Токены сервисов разделены по API и адресу. При смене API введённый токен очищается. Старые настройки без API продолжают означать Gitea.

Для GitHub укажите `https://github.com` (принимается и `https://api.github.com`), репозиторий `владелец/репозиторий` и каталог XML. GitHub Enterprise пока не поддерживается. Рекомендуется fine-grained PAT только нужного репозитория с **Contents: Read-only**. Организация может требовать одобрение/SSO. Мастер не повышает права автоматически; проверка реального private-репозитория с таким PAT остаётся отдельным пилотом.

После открытия ветки мастер показывает её SHA. Создайте индекс по кнопке и отметьте объекты. Мастер читает XML-описания для SQLite и запрашивает содержимое нужных файлов при предпросмотре и сборке. Для GitHub XML читаются read-only GraphQL-пакетами, размер и Git-хеш каждого файла проверяются. Бинарные/усечённые тексты читаются адресно через Blob API. Полный ZIP и Git-клон не создаются. Если доступна совпадающая локальная выгрузка с индексом, мастер переиспользует проверенные файлы и факты. Для каждой ветки можно выбрать папку индекса. Интервал 0 выключает проверку SHA.

В открытой ветке введите **Номер задачи Git**, например ERP-123, и нажмите **Найти**. Мастер проверяет сообщения коммитов за последние 90 дней или за всю историю по выбору. Он показывает затронутые объекты в дереве и отдельно считает пути, которым нельзя сопоставить объект текущей ревизии. **Отметить найденные** добавляет их к ручному выбору, а **Сбросить отбор** возвращает полное дерево. Для GitHub пути вычисляются сравнением деревьев: ограничение 3000 файлов обычного commit API не обрезает отбор. Merge сравнивается с первым родителем; переименование учитывает оба пути, удалённые объекты сопоставляются только с существующими объектами открытой ревизии. Поиск можно выполнить до создания индекса. Предпросмотр и сборка используют состояние объектов в открытой ревизии.

Оба источника принимают XML-выгрузку основной конфигурации для формирования CF. Попытка открыть выгрузку расширения показывает ошибку.

При отказе доступа или лимите API мастер сохраняет прежний каталог/индекс и показывает безопасную ошибку. PAT не записывается в журналы и paths.json; в сообщениях не выводится ответ сервера. Настройки и кэш Gitea сохраняют прежние пути, GitHub использует отдельную идентичность. Изменения не включают новый EXE.

## Индекс зависимостей SQLite

Откройте XML-выгрузку, укажите **Папку индекса зависимостей** и нажмите **Создать индекс**. По умолчанию мастер использует `%LOCALAPPDATA%\CF-Wizard\indexes`. База хранит структуру полей, состав определяемых типов и связи регистров с документами-регистраторами.

После обновления XML-выгрузки нажмите **Обновить индекс**. Мастер сравнивает хеши описаний объектов, пересчитывает изменившиеся записи, добавляет новые и удаляет записи исчезнувших объектов. После обновления внизу окна появятся счётчики.

Для каждой папки выгрузки мастер создаёт отдельный файл SQLite. При переключении выгрузки мастер предложит выбрать папку для её индекса и запомнит выбор. Индексы нескольких выгрузок могут находиться в одной общей папке.

При предпросмотре мастер сверяет используемые записи с XML. Для отсутствующих и устаревших записей он читает исходники. Журнал показывает число обращений к индексу и переходов на XML.

## Создание технической конфигурации

1. Укажите папку полной Designer XML-выгрузки основной конфигурации или её `Configuration.xml`. Путь можно вставить вручную, в том числе к доступной сетевой папке.
2. Найдите объекты в дереве по русскому названию типа или имени. Для отметки щёлкните по флажку в колонке **Выбор** или нажмите пробел на выделенном объекте. Щелчок по названию выделяет строку. Фильтр **Только выбранные** показывает отмеченные объекты и учитывает введённый поиск.
3. Нажмите **Предпросмотр**, чтобы рассчитать зависимости. Раскройте группы на вкладке **Заглушки** и проверьте причины включения. Группы названы по типу объектов из колонки **Требуется для**. Снять флажок **В CF** можно, когда сборщик нашёл ссылки на заглушку только в комментариях BSL. Если заглушка встречается в нескольких группах, её отметки меняются вместе.
4. В **Настройках** выберите папку результата и **Способ сборки**. **Авто** использует Конфигуратор версии 8.3.27.2214. В режиме **ibcmd** или **Конфигуратор** можно указать соответствующий исполняемый файл другой установленной версии. В необязательное поле задачи можно вписать номер, дату или комментарий. Мастер использует текст в начале имени папки комплекта и заменяет недопустимые символы.
5. Нажмите **Собрать CF**. Мастер сверит исходные файлы и подготовит XML и настройки объединения по плану предпросмотра. При исключении заглушек он пересчитает состав с учётом снятых флажков. Затем мастер соберёт CF и сверит её обратной выгрузкой.

В выбранной папке результата мастер создаёт отдельную папку комплекта с файлом `.cf` и настройками `.merge-settings.xml`. Если номер задачи пуст, имя папки составляется из локальной даты и времени в формате `ГГГГ-ММ-ДД_ЧЧ-ММ-СС`. Если такое имя занято, мастер добавляет числовой суффикс. Номер задачи, когда он указан, используется в начале имени папки. Временный XML-комплект очищается после сборки или ошибки. Сборка подтверждает техническую целостность пакета. Применение CF к получателю и функциональная проверка выполняются отдельно.

## Журналы

По умолчанию мастер пишет журналы в `%LOCALAPPDATA%\CF-Wizard\logs`. Чтобы изменить расположение, укажите свою **Папку журналов**. Кнопка **Папка журналов** на главной панели открывает эту папку. Кнопка **Открыть журнал** показывает журнал последней операции в отдельном окне мастера. Журнал доступен после создания или обновления индекса, предпросмотра и сборки. Текст можно выделить и скопировать. Мастер указывает путь к журналу в сообщении об ошибке. В журнале индекса указаны источник, файл SQLite, время работы и число добавленных, изменённых, удалённых и переиспользованных записей. В журнале сборки видны этапы подготовки, сборки, обратной выгрузки и очистки.

При ошибке ищите отчёт в подпапке **Ошибки** внутри выбранной папки журналов. В нём есть версия мастера, идентификатор процесса, последний шаг и путь к журналу операции, когда он уже создан. При аварийном завершении Python сохраняет трассировку потоков. Если выбранная папка недоступна, мастер использует `%LOCALAPPDATA%\CF-Wizard\logs\Ошибки`. После штатного закрытия отчёт сохраняется, только если зарегистрирована ошибка.

## Сборка EXE

`cf_wizard/composition.py` определяет состав пакета и правила исключения заглушек. `cf_wizard/application.py` содержит сценарии и интерфейсы. `cf_wizard/adapters.py` работает с XML, сборщиком и платформой. `cf_wizard/ui` содержит HTML, стили и справку. `cf_wizard/qt_view.py` связывает форму с командами мастера и системными диалогами. `cf_wizard_qt.py` связывает слои.

Для пересборки из каталога инструмента используйте отдельное окружение CPython 3.12 x64 на Windows.

```powershell
python -m pip install PySide6-Essentials==6.10.2 PySide6-Addons==6.10.2 PyInstaller==6.18.0
python -B build_cf_wizard_exe.py .\CF-Wizard-0.7.1-git-pilot-windows-x64.exe
```

Перед распространением проверьте условия лицензирования встроенных компонентов. Лицензия значков Lucide доступна из окна **О программе**. [Репозиторий сборщика](https://github.com/alonehobo/1c-partial-cf), [лицензии Qt for Python](https://doc.qt.io/qtforpython-6/licenses.html).
