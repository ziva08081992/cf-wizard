# Проверка Rust-пилота 0.8.0-rust.1

Проверено 13.11.2026 на Windows x64, платформа 1С 8.3.27.2214. Исполняемый файл: `CF-Wizard-Rust-0.8.0-rust.1.exe`.

- Размер: **8 082 944 байта / 7,71 МиБ**.
- SHA256: `ae67c89734424e56c121ff558f0455f70f06322f7fffb702d0d2665ca9a5d06b`.
- Release-сборка с Thin LTO и статической C-runtime; Python, Qt и Visual C++ runtime DLL в импортах отсутствуют. Системные библиотеки Windows и установленный WebView2 используются штатно.

## Код и алгоритм

`cargo fmt --all --check`, `cargo check --workspace --locked`, `cargo test --workspace --locked`, `cargo clippy --workspace --all-targets --locked -- -D warnings` прошли с настройками финальной сборки. **55 тестов**: application 1, domain 5, infrastructure 48, desktop 1.

16 сквозных эталонов текущего helper 0.7.3 проверены в двух режимах: без индекса и с закреплённым legacy SQLite. Совпадают состав, обязательность/причины заглушек, члены, предупреждения, весь staging inventory, байты файлов и merge-settings. Дополнительно проверены запросы, формы, комментарии BSL, циклы, глубокие пути, DefinedType, wildcard, регистраторы и минимальные дочерние объекты.

Проверены смена SHA без XML-изменений, инкремент одной XML, удаление/добавление, регистраторы, COW legacy без изменения исходной БД, повреждённые facts/контракты, межпроцессная блокировка и принудительное завершение отдельного тестового writer в транзакции. Старые опубликованные байты/mtime индекса сохраняются, последующее обновление проходит.

Для Git использованы API fixtures обеих стратегий: страницы до пустой страницы, деревья, first-parent merge/initial diff, 3501 изменённый файл, переименования, удаления, mode changes, batch/GraphQL и отказ от частичных ошибочных данных. Кэш отдельно проверен на перезапуске и новом SHA; каталог из 10 000 файлов переиспользуется без глубокого копирования. Отмена прерывает дальнейшие запросы дерева.

Windows Credential Manager проверен фактическими save/read/delete своей временной тестовой записи, включая UTF-16LE/non-BMP. Пользовательские токены не читались и не менялись.

Независимые алгоритмическое и смысловое read-only review завершены без открытых подтверждённых дефектов. Исправлены найденные проверки путей и frozen source, лишние квадратичные проходы, отмена, поздние ответы, ветки и удаление токена выбранного сервера. Полный протокол: OpenSpec `port-cf-wizard-to-rust` в основном workspace.

## Готовый EXE

Файл скопирован вне исходников/Cargo, запуск выполнен из `C:/Windows/Temp` с PATH только Windows/System32. В дереве процессов наблюдались Rust-приложение и `msedgewebview2.exe`; Python/Qt не запускались.

Внешний замер: Stopwatch непосредственно перед Start-Process → появление отчёта DOM-ready, опрос 5 мс. ОС-кэш не очищался; первый запуск создавал отдельный профиль WebView2, следующие использовали его.

| Прогон | Процесс → готовность окна |
|---|---:|
| Первый в этом профиле | 0,554 с |
| Повторный | 0,458 с |
| Ещё один | 0,472 с |

Внутренние таймеры окна измеряют более узкую границу; они не подменяют эту таблицу. В историческом отчёте 0.7.3 onefile было 5,51 с повторного запуска, но старый EXE заново в этом прогоне не измерялся.

Настоящее окно прошло 13 автоматических действий: открытие рабочей XML-выгрузки, русское дерево, фокус строки без отметки, немедленные отметка/снятие флажка и подтверждение native state, фильтр выбранных, предпросмотр, встроенный журнал, справка, свободный комментарий, открытие Git-диалога, GitHub/default server и контраст элементов. Техническая проверка не заменяет визуальную приёмку пользователем.

Суммарный sampled working set дерева WebView2-процессов в отдельном прогоне составлял около 479 МиБ. Общие страницы могут учитываться несколько раз. Уменьшение EXE и времени старта не означает такого же уменьшения памяти браузерного интерфейса.

## Реальные CF

Финальным EXE собраны и обратно выгружены технические CF из рабочих XML. Для каждого прогона создавались новые временные файловые базы; существующие базы не изменялись.

| Объект | Способ | Сборка с проверкой | Файлов staging |
|---|---|---:|---:|
| CommonModule.ZipАрхивы | Конфигуратор | 3,73 с | 6 |
| CommonModule.ZipАрхивы | ibcmd | 6,60 с | 6 |
| Catalog.Валюты | Конфигуратор | 8,99 с | 36 |

Это результаты конкретных прогонов, а не гарантированное время любой конфигурации. В receipt подтверждены native exit/DumpResult, readback XML/QName/xml:space/BSL, неизменность staging и SHA256 CF. В каждой итоговой папке ровно CF и merge-settings.

Проверка публикации также отклоняет результат внутри XML-источника и изменение уже проверенных файлов. Ошибка, показанная в пилоте из-за короткого/полного Windows-пути временной папки, исправлена; нормализованные aliases покрыты тестом и реальным повторным прогоном.

## Границы

- Реальные личные подключения к закрытым Gitea/GitHub в этом цикле не использовались. Следующий этап — пользовательский пилот с собственным доступом.
- Объединение CF с целевой ERP, проверка бизнес-сценариев и совместимость всех возможных объектов в целевой базе не выполнялись.
- Нативный ручной выбор файлов/папок Windows не автоматизировался; обработчики и начальные пути проверены по коду.
- Максимальные объёмы CF/истории отдельно не измерялись. История сообщений и CF при публикации обрабатываются в памяти; WebView2 остаётся отдельным браузерным runtime.
- Commit, push, PR, публикация релиза и повторный перевод компьютера в сон не выполнялись.

Подробные машинные отчёты, native receipts и gzip-журналы находятся в соседней служебной папке `cf-wizard-rust-qa-20261113`; они не нужны для запуска EXE.
