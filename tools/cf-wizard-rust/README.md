# CF Wizard · Rust 0.8.8

Исправлены группы заглушек, добавлено ограниченное параллельное чтение состава объектов Git и измерения этапов предпросмотра; [границы проверки версии 0.8.8](../../docs/reports/cf-wizard-0.8.8-acceptance.md).

Прикладные source readers, frozen projection/package/merge compiler и независимые guards описаны в [профиле ядра](../../docs/architecture/owned-source-profile.md). Старые producers используются только в offline compatibility tests. После смены semantic versions прежний индекс требует явного обновления; предпросмотр его не переписывает. [Изменения и фактические границы проверок](../../docs/releases/v0.8.7.md).

Пилотная Windows-программа для создания технической **CF** из локальной XML-выгрузки или файлов выбранной ветки Gitea/GitHub. Движок, SQLite, Git, хранение токенов, сборка и управление окном перенесены на Rust. HTML/CSS/JavaScript отвечают за отображение. Python и Qt при работе EXE не используются.

## Запуск и требования

Запустите `CF-Wizard-Rust-0.8.0-rust.2.exe`. Установщик и отдельный Python не нужны. Нужны Windows x64, Microsoft Edge WebView2 Runtime и установленная 64-разрядная платформа 1С. Проверены оба способа сборки на **8.3.27.2214**. Режим «Авто» выбирает Конфигуратор именно этой версии; другую установленную версию можно указать вручную.

В rust.2 ускорены свежие файловые проверки Windows и повторное построение заглушек внутри одного предпросмотра. Кэш используется только при неизменных входах; сканирование зависимостей и проверки актуальности сохраняются. Полные XML-деревья не кэшируются, формат SQLite и настройки совместимы с rust.1.

Мастер работает с основной конфигурацией. XML расширения отклоняется; CFE не собирается. CF проверяется обратной выгрузкой. Такая проверка подтверждает целостность технического комплекта; совместимость объединения с целевой базой проверяет разработчик.

## Как собрать CF

1. Откройте **Настройки**. Укажите папку результата, папку журналов и способ сборки. Задачу или комментарий можно написать в любом формате; недопустимые для имени папки символы заменяются. Пустое поле даёт имя по текущей дате и времени.
2. Для **Локальной папки** выберите XML-выгрузку или её `Configuration.xml`. Объекты загружаются автоматически; сохранённый путь открывается и при следующем запуске.
3. Для **Git** откройте подключение, выберите API Gitea/GitHub, HTTPS-сервер, `владелец/репозиторий`, каталог XML (например, `config`), ветку и папку кэша. Введите персональный токен чтения. Флажок «Запомнить» сохраняет его в Диспетчере учётных данных Windows. Перенос EXE на другой компьютер не переносит токен.
4. Выберите папку индексов и нажмите **Создать индекс**. Для Git это необходимо до предпросмотра. Сохранённый индекс используется повторно; новая SHA с теми же XML не требует обновления. При изменившихся XML мастер предлагает **Обновить индекс** и пересчитывает изменившиеся записи по кнопке. Старые SQLite импортируются в отдельный `.rust.sqlite3`; исходный файл не перезаписывается.
5. Отметьте объекты в дереве. Щелчок по названию меняет фокус; отметку меняют флажок или пробел. Фильтр **Только выбранные** показывает отмеченные объекты. В Git можно найти коммиты по задаче за 90 дней, всю историю или произвольное положительное число дней, затем отметить найденные объекты.
6. Нажмите **Предпросмотр**. Он определяет зависимости и показывает заглушки; staging и CF на этом шаге не создаются. Заглушки сгруппированы по типу объекта, которому нужны. Обязательные снять нельзя; ссылки только из комментариев BSL можно исключить.
7. Нажмите **Собрать CF**. Используется подготовленный план; без исключений заглушки повторно не ищутся. При изменении исходных файлов потребуется новый предпросмотр. Сборка выполняется в новых временных базах, затем проверяется обратной выгрузкой. **Открыть комплект** показывает папку с двумя файлами: `.cf` и `.merge-settings.xml`.

Пути и папки индексов сохраняются отдельно для источников. При смене источника предлагается выбрать другую папку SQLite. Проверка SHA Git только сообщает об изменениях; она не обновляет индекс автоматически. Интервал в секундах задаётся в подключении: 0 отключает опрос, иначе допустимо 30–86400 секунд.

## Справка и ошибки

**Справка / F1** открывает инструкцию внутри программы. **Открыть журнал** показывает последнюю операцию в том же приложении, **Папка журналов** открывает все журналы. Индексирование, предпросмотр, подключение, сборка и ошибки протоколируются. Журналы — сжатые JSON-lines (`.jsonl.gz`); сведения об ошибках находятся в подпапке `Ошибки`. Просмотр ограничен 32 МиБ распакованного журнала.

Временные XML и базы удаляются после операции; журналы сохраняются. Постоянный Git-кэш и SQLite сохраняются для последующих запусков. Настройки по умолчанию: `%LOCALAPPDATA%/CF-Wizard/paths.json`. Токен в этот файл и в журналы не записывается. Сохранённые имена credentials совместимы с предыдущей версией и разделены между провайдерами/серверами.

## Сборка из исходников

Установите Rust MSVC x64 и Microsoft C++ Build Tools. Проверенный toolchain: Rust 1.99.1. Из этой папки:

```powershell
cargo fmt --all --check
cargo check --workspace --locked
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo build --release --locked
```

EXE: `target/release/cf-wizard-rust.exe` (или каталог из `CARGO_TARGET_DIR`). Ресурсы интерфейса встроены в бинарный файл. `Cargo.lock` зафиксирован. Обычная сборка и тесты не запускают Python. Python-генераторы в `tests/fixtures` нужны только для повторного получения эталонов 0.7.3; сохранённые эталоны уже включены.

Слои: `domain` — правила и модели; `application` — сценарий сборки и порты; `infrastructure` — источники, стратегии API, движок, SQLite, платформа, журналы и публикация; `desktop` — Wry/WebView2, фоновые операции и представление.

## Проверки пилота

Фактические результаты текущей сборки и границы проверки приведены в `VALIDATION.md`. Тесты включают сравнение полного XML-комплекта с 0.7.3, Git API fixtures, сохранность SQLite при аварии писателя, Windows Credential Manager на собственной тестовой записи и запуск настоящего окна. Проверка на личных токенах и закрытых репозиториях пользователя отдельно не объявляется пройденной.
